# E1 — Service de données Concorde (C1–C5)

## 1. Contexte, acteurs, objectifs et contraintes

Concorde qualifie la cohérence et la confiance d'un rapprochement DVF+ × DPE ADEME × aléas Géorisques. Il ne prédit ni prix ni tarif : son objet est la qualité du rapprochement.

Les acteurs sont un particulier qui veut comprendre les limites des données, un analyste qui vérifie un cas avant revue humaine, et l'exploitant qui assure la reproductibilité. La contrainte structurante est l'absence d'Internet pendant la démonstration : les sources sont rejouées depuis des fixtures versionnées et non depuis des services distants.

## 2. Spécifications fonctionnelles et techniques

La chaîne doit démontrer cinq modalités de collecte : fichier DVF+/aléas, service web BAN local, page Géorisques depuis snapshot, PostgreSQL et système big data Spark pour les DPE. Les données sont nettoyées, rapprochées par parcelle, agrégées et exposées par une API REST.

**Décision.** La parcelle est la clé de rapprochement ; les ambiguïtés et les absences de DPE restent visibles au lieu d'être artificiellement résolues. L'incertitude est une sortie du produit, non un défaut à masquer.

Le modèle PostgreSQL ne conserve que références communales et aléas. Il exclut toute identité, adresse complète ou propriétaire. Voir le [MCD/MPD](../../docs/data-model.md) et le [registre RGPD](../../docs/rgpd.md).

## 3. Réalisation data et API

Les collecteurs sous `src/concorde/collect/` sont déclenchés par `python -m concorde.collect`. Les six collecteurs produisent un manifeste et des fichiers bruts locaux. Spark lit le DPE avec Java 17 ; PostgreSQL est peuplé de manière idempotente par `scripts/import_postgres.py`.

Le nettoyage `python -m concorde.clean` homogénéise les formats, élimine les entrées invalides et produit `data/processed/rapprochements.parquet`. Le tableau avant/après est archivé dans [nettoyage_avant_apres.md](../annexes/nettoyage_avant_apres.md).

L'API `api/data/` expose `/communes?departement=33`, exige `X-API-Key` et publie son OpenAPI localement. Les requêtes PostgreSQL et Spark SQL sont dans [queries.md](../../docs/queries.md).

## 4. Tests, sécurité et reproductibilité

```bash
docker compose up -d postgres
source scripts/spark-env.sh
uv run python scripts/import_postgres.py
uv run python -m concorde.collect
uv run python -m concorde.clean
uv run pytest tests/data tests/api/test_api_data.py -q
```

La suite vérifie Spark, PostgreSQL, sources web rejouées et filtre API. Java 17 est fixé car Spark 3.5 échoue avec Java 26 (`Subject.getSubject is not supported`). L'API exige une clé par rôle et n'expose qu'une synthèse communale.

## 5. Bilan, limites et perspectives

La chaîne couvre C1 à C5 avec des preuves exécutables : aucune source distante n'est requise le jour J. La fixture n'est pas une collecte nationale et ne doit pas être présentée comme telle. Les sources réelles peuvent être rejouées en mode connecté avec `CONCORDE_OFFLINE=false`, puis refigées avant la démo.

**Preuves à montrer :** `data/raw/_manifest.json`, le rapport Spark, l'OpenAPI de l'API data et le test de filtre. La synthèse est dans [matrice-preuves.md](matrice-preuves.md).
