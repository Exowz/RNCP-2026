# E4 — Application intégrant le service IA (C14–C19)

## 1. Contexte, acteurs, objectifs et contraintes

L'application s'adresse à un particulier et à un analyste crédit. Ils lisent le même verdict avec des niveaux de détail différents ; le calcul ne change jamais selon le profil. L'interface doit être locale, accessible, sécurisée et livrable hors ligne.

## 2. Spécifications et architecture

Les personas, user stories, critères d'acceptation et exigences WCAG/RGAA sont dans [specs-fonctionnelles.md](../../docs/specs-fonctionnelles.md). L'architecture est décrite dans [architecture.md](../../docs/architecture.md) : app Jinja2 → API FastAPI → artefact local, avec PostgreSQL et Spark en amont de l'entraînement.

**Décision.** Le rendu serveur HTML est préféré à une SPA : il évite une chaîne npm et tout CDN, donne la maîtrise du DOM pour l'accessibilité et reste stable sans Internet.

## 3. Réalisation applicative et sécurité

L'application fournit choix de cas, résultat en trois axes, réserves, transparence des règles et tableau de bord local. Elle gère l'indisponibilité de l'API par une page 503 explicite plutôt que par une réponse fabriquée. Les APIs utilisent clés par rôle, validation Pydantic, CSP, anti-clickjacking, pseudonymisation et garde-fou socket ; voir [securite.md](../../docs/securite.md).

Les contrôles d'accessibilité sont vérifiables : lien d'évitement, focus visible, contrôles natifs et libellés, `aria-live`, tableaux structurés, contraste et absence d'information portée par la seule couleur.

## 4. Tests, CI/CD et livraison

```bash
source scripts/spark-env.sh
uv run pytest tests/app tests/api -m "not local_service" -q
docker compose -f docker-compose.delivery.yml build
docker compose -f docker-compose.delivery.yml up -d --no-build
curl --fail http://127.0.0.1:8000/sante
```

La preuve de préproduction est archivée dans [livraison-docker-2026-08-24.md](../annexes/livraison-docker-2026-08-24.md) : image locale, statut `healthy`, sonde, POST HTML et journaux corrélés. `pull_policy: never` et `--no-build` empêchent le pull au démarrage. C18 est démontré par la CI GitHub verte ; C19 par l'image Docker démarrée hors registre.

## 5. Bilan, limites et perspectives

L'application est un consommateur réel du service IA et non un import du moteur. La livraison est localement reproductible. Le candidat est seul : [pilotage.md](../../docs/pilotage.md) montre un tableau personnel, une Definition of Done et un REX, mais C16 reste partiel car aucun collectif ne doit être simulé. L'image est lourde ; une image runtime minimaliste est une amélioration explicitement identifiée.
